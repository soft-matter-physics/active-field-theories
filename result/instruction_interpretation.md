## Model selection

The observed velocity snapshots are converted into radial energy spectra as a function of time. The AMH and AN neural networks then independently estimate the parameters of their own candidate model.

These neural-network estimates are parameter proposals. The final model decision is made by simulating both candidate models with their proposed parameters and comparing the resulting spectra with the observed spectrum.

Each candidate is simulated $R=5$ times. For candidate $c\in\{\mathrm{AMH},\mathrm{AN}\}$, the discrepancy is
$$

d_c

=

\frac{1}{R N_k}

\sum_{r=1}^{R}\sum_k

\left[

\log_{10}\langle E_{\mathrm{obs}}\rangle_t(k)

-

\log_{10}\langle E_{c,r}\rangle_t(k)

\right]^2.

$$
Here:
- $E_{\mathrm{obs}}$ is the energy spectrum of the observed velocity field;
- $E_{c,r}$ is the spectrum from realization $r$ of candidate $c$;
- $\langle\cdot\rangle_t$ means averaging over the saved time frames;
- $N_k$ is the number of radial wavenumber bins;
- $d_c$ is the mean squared difference between the two log spectra.

A smaller $d_c$ means that candidate $c$ reproduces the observed spectrum more closely. The relative winner is therefore
$$

\operatorname*{arg\,min}_{c\in\{\mathrm{AMH},\mathrm{AN}\}}d_c.

$$This comparison always produces a winner, even when both models reproduce the observation poorly. It answers only:
> Which of AMH and AN is closer to the observation?

To express the strength of this relative preference, define
$$

\ell

=

\ln\left(

\frac{d_{\mathrm{AN}}+\epsilon}

{d_{\mathrm{AMH}}+\epsilon}

\right).

$$

- $\ell>0$ favors AMH because $d_{\mathrm{AMH}}<d_{\mathrm{AN}}$.
- $\ell<0$ favors AN because $d_{\mathrm{AN}}<d_{\mathrm{AMH}}$.
- $\ell=0$ means equal discrepancies.

Using 700 held-out AMH cases and 700 held-out AN cases, this quantity was converted into a calibrated AMH probability:
$$

P(\mathrm{AMH}\mid\ell)

=

\frac{1}{1+\exp(-a\ell)},

\qquad

a=6.709361.

$$
This probability is conditional on the choice being restricted to AMH or AN. For example, a large $P(\mathrm{AMH})$ means that AMH is strongly preferred over AN. It does not by itself prove that AMH is a good absolute description of the observation.


The scale-free separation score is
$$

C

=

\frac{|d_{\mathrm{AN}}-d_{\mathrm{AMH}}|}

{d_{\mathrm{AN}}+d_{\mathrm{AMH}}},

\qquad 0\leq C<1.

$$

- $C=0$ means that the discrepancies are equal.
- A value near 1 means that one discrepancy is much smaller than the other.
$C$ measures separation between the two candidates. It is not a probability.
### Independent absolute goodness of fit

Relative model selection cannot tell whether the winning model actually fits well. To test this, the AMH discrepancy is compared with discrepancies obtained when AMH is known to be the correct model. The AN discrepancy is compared with an equivalent reference set for AN.

For candidate $c$, the goodness-of-fit value is
$$

p_{\mathrm{GOF},c}

=

\frac{

1+\#\{d\in\mathcal D_c:d\geq d_c^{\mathrm{obs}}\}

}{701}.

$$
$\mathcal D_c$ contains 700 discrepancies from held-out observations generated by candidate $c$. The numerator counts how many of those normal reference errors are at least as large as the new error.

The interpretation is:
- large $p_{\mathrm{GOF},c}$: the new discrepancy is ordinary for model $c$;
- small $p_{\mathrm{GOF},c}$: the discrepancy is unusually large for model $c$, so the model is a poor absolute fit.

At $\alpha=0.01$, candidate $c$ passes when

$$

p_{\mathrm{GOF},c}\geq0.01.

$$
The same test can be written using the calibrated thresholds
$$

T_{\mathrm{AMH}}=5.284495,

\qquad

T_{\mathrm{AN}}=1.272512.

$$
The normalized discrepancy is
$$

G_c=\frac{d_c}{T_c}.

$$
- $G_c\leq1$: candidate $c$ passes its absolute spectrum test.
- $G_c>1$: candidate $c$ fails its absolute spectrum test.
The final decision is
```text
only AMH passes -> AMH
only AN passes -> AN
both pass -> relative winner
both fail -> NEITHER
```

Thus the relative comparison chooses between AMH and AN, while the absolute test checks whether either candidate is accurate enough.
### Parameter uncertainty
A single neural-network parameter estimate does not show how accurate that estimate is likely to be. Parameter uncertainty is therefore reported as an interval around each predicted value.

For parameter $\theta_j$, the prediction error on held-out case $i$ is measured in logarithmic space:
$$

r_{ij}

=

\left|

\log_{10}|\theta_{ij}|

-

\log_{10}|\widehat\theta_{ij}|

\right|.

$$
This measures the error as a multiplicative error. For example, predicting twice the true value and predicting half the true value have the same error size in log space.

  

The held-out errors are ranked, and a value large enough to contain 90% of them is selected. This procedure is called split-conformal calibration. In plain terms, it uses observed errors on separate test simulations to determine how wide future parameter intervals should be.

If the resulting multiplicative factor is $f_j$, the interval is
$$

|\theta_j|

\in

\left[

\frac{|\widehat\theta_j|}{f_j},

|\widehat\theta_j|f_j

\right].

$$
The known physical sign is restored afterward. For example, the AMH activity factor is $f_{\widetilde{k}}=1.186$. If
$\widehat{\widetilde{k}}=-0.50$, the interval is approximately

$$

\widetilde{k}\in[-0.593,-0.422].

$$

The word **coverage** has a simple meaning here. Suppose 100 simulations have known true parameter values and 88 of those true values fall inside their reported intervals. The empirical coverage is then $\frac{88}{100}=0.88$


The intervals were designed for 90% coverage, so coverage near 0.90 is expected for new data generated in the same way as the calibration data. It does not mean that exactly 90 out of every 100 cases must be covered; the observed fraction fluctuates because the test sample is finite.

  

For $\lambda\neq0$, the dynamics differs from the AMH dynamics used during training and calibration. Therefore, 90% coverage is not guaranteed. A low coverage value in those datasets means that the neural network's parameter estimates are no longer quantitatively reliable under the modified dynamics.

## Meaning of every file
### `config.json`
This file records the numerical settings and paths needed to reproduce the experiment:

- `samples: 100`: 100 independently chosen parameter sets for each base family;
- `lambdas`: the four nonzero AMH modifications;
- `realizations: 5`: the number $R$ used to calculate each discrepancy;
- `seed`: the master random seed;
-  paths to the trained models, scalers, calibration file, and output folder;
- `grid_size: 128`: each physical field has a $128\times128$ grid;
- `grid_spacing: 1.0`, giving box length $L=N_gh=128$;
- `saved_frames: 50`: 50 velocity snapshots per trajectory;
- 50 frames supplied to both neural networks;
- 5,000 integration steps for AMH observations;
- 4,000 integration steps for AN observations and candidate resimulations;
- AMH activity sampled from $[-1.0,-0.05]$.

### `model_selection_calibration_128_500.joblib`

This is the complete machine-readable calibration object used during model selection. 
It contains:

1. the logistic conversion from $\ell$ to $P(\mathrm{AMH})$;
2. the 700 AMH and 700 AN reference discrepancies;
3. the two absolute-fit thresholds and the choice $\alpha=0.01$;
4. the multiplicative factors used for parameter intervals;
5. the required resimulation number $R=5$.
### `calibration_summary.json`

This is a short, readable summary of the calibration object. 
It reports:

- `logistic_slope`: the fitted value $a$ in the logistic equation;
- `logistic_loo_accuracy`: classification accuracy when each calibration case is tested using a logistic fit made from all the other cases;
- `logistic_loo_brier`: mean squared error between the predicted probability and the true AMH/AN label; smaller is better;
- `logistic_loo_log_loss`: another probability-error measure that strongly penalizes confident wrong predictions; smaller is better;
- the AMH and AN absolute-fit thresholds;
- the fraction of held-out cases accepted by the absolute test;
- the parameter interval factors and their coverage checks.


`loo` means **leave one out**: one calibration case is temporarily removed, the method is calibrated on the remaining cases, and the removed case is then tested. Repeating this for every case checks whether the calibration generalizes to data that were not used in that particular fit.

These values describe the calibration dataset, not the 600 new experiment cases.

### `logistic_reliability.csv`

This file checks whether the predicted AMH probabilities agree with the observed AMH frequencies on the 1,400 held-out calibration cases.

The cases are sorted by their predicted probability and divided into four groups of 350. The columns are:

- `bin`: probability range covered by the group;
- `n`: number of calibration cases in the group;
- `mean_predicted_p_amh`: mean predicted AMH probability in that group;
- `observed_amh_fraction`: fraction of cases in that group that are actually AMH.

For example, if a group has mean predicted probability 0.80 and approximately 80% of its cases are AMH, the probabilities are well calibrated in that group. Good calibration therefore means that `mean_predicted_p_amh` and `observed_amh_fraction` are similar.


This check applies to standard held-out AMH/AN simulations. It does not prove that probabilities remain calibrated for the modified-$\lambda$ data.
### `cases.pkl`

This is the detailed case-level table. It has 600 rows and 47 columns: one row for every evaluated observation.


The 600 rows contain:
- 100 standard AMH cases;
- 100 cases for each of the four nonzero $\lambda$ values;
- 100 standard AN cases.
#### Identity and true-parameter columns

- `dataset`: experimental group.
- `sample`: parameter-set number from 0 to 99. Equal sample numbers connect matched AMH cases across different $\lambda$ values.
- `true_family`: model that generated the observation, AMH or AN.
- `lam`: value of $\lambda$; empty for AN.
- `k_tilde`, `kp`, `b`: true AMH parameters; empty for AN.
- `kappa`, `zeta`: true AN parameters; empty for AMH-family cases.
- `status`: `ok` or `diverged`. All 600 cases in this folder are `ok`.
#### Discrepancy and relative-selection columns

- `d_AMH`, `d_AN`: spectral discrepancies for the two candidates.
- `relative_winner`: candidate with the smaller discrepancy.
- `family_correct`: true when the relative winner equals the generating model.
- `log_discrepancy_ratio`: $\ell=\ln(d_{\mathrm{AN}}/d_{\mathrm{AMH}})$.
- `separation`: the scale-free separation $C$.
- `p_amh`: calibrated probability favoring AMH over AN.
- `winner_probability`: probability assigned to whichever model is the relative winner. It equals `p_amh` for an AMH winner and $1-P(\mathrm{AMH})$ for an AN winner.
#### Absolute-fit columns

- `p_gof_AMH`, `p_gof_AN`: values showing how ordinary or unusual each candidate discrepancy is relative to its calibration cases.
- `normalized_d_AMH`, `normalized_d_AN`: $G_c=d_c/T_c$.
- `AMH_adequate`, `AN_adequate`: whether each candidate passes its absolute test.
- `winner_adequate`: whether the relative winner passes its absolute test.
- `final_decision`: `AMH`, `AN`, or `NEITHER` after the absolute tests.
- `accepted_correct`: true when the final decision equals the generating family. A `NEITHER` result is counted as false even if the relative winner was the correct family.

#### Parameter prediction and interval columns

For every candidate parameter, the table stores
```text
<MODEL>_<parameter>_pred
<MODEL>_<parameter>_lower
<MODEL>_<parameter>_upper
```
  These are the predicted value and the lower and upper limits of its calibrated interval.

  For parameters belonging to the true generating family, the table also stores
```text
<MODEL>_<parameter>_covered
```

This value is true when the known simulation parameter lies inside the reported interval. It is empty for the wrong-family candidate because that candidate has no corresponding true parameter value.
### `cases.csv`

This is a plain-text export of the same 600-row case table. 

Use `cases.pkl` for exact Python analysis because it preserves Boolean and numeric data types more reliably. In the CSV file, missing values appear as empty fields.
### `summary.csv`

This file summarizes classification and absolute-fit results separately for standard AMH, each $\lambda$ value, and AN.

Columns:
- `n`: number of successfully evaluated cases in the group;
- `relative_family_accuracy`: fraction for which the smaller-discrepancy model is the true generating family;
- `accepted_correct_rate`: fraction for which the final decision is the true family after applying the absolute tests;
- `adequacy_acceptance_rate`: fraction for which the relative winner passes its absolute test;
- `neither_rate`: fraction assigned `NEITHER`;
- `mean_separation`: average value of $C$;
- `mean_winner_probability`: average calibrated probability assigned to the relative winner;
- `mean_p_gof_AMH`, `mean_p_gof_AN`: average absolute-fit values for the two candidates.

For example, `relative_family_accuracy = 1.0` and `accepted_correct_rate = 0.95` mean that the correct family had the smaller discrepancy in every case, but 5% of the cases were rejected as `NEITHER` by the absolute-fit test.
### `parameter_interval_coverage.csv`

This file checks how often the reported parameter intervals contain the known true simulation parameters.

Columns:
- `dataset`, `true_family`, `lam`: experimental group;
- `parameter`: parameter being checked;
- `n`: number of cases included in the check;
- `empirical_coverage`: number of true values inside their intervals divided by $n$.

For example,
```text
dataset = AMH
parameter = k_tilde
n = 100
empirical_coverage = 0.88
```
means that the true $\widetilde{k}$ value was inside its reported interval in 88 of the 100 standard AMH cases.

Coverage near 0.90 is the expected result for standard AMH/AN observations, because these are generated in the same way as the data used to determine the interval widths. Coverage for $\lambda\neq0$ measures robustness to modified dynamics. A much smaller value means that the network can still identify the model family but its numerical parameter estimates are no longer dependable.
